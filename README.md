# Screen Translator

Windows-приложение WPF для выделения текста на экране, OCR, локального перевода через Hy-MT2 или перевода через DeepL, словаря и тренировки слов.

## Структура проекта

- `UI` — окна, меню и оверлей.
- `OCR` — движки распознавания, предобработка изображений и исправление текста.
- `Translation` — общий интерфейс переводчика, DeepL, локальная модель и установка движка.
- `Dictionary` — хранение слов, карточки и логика тренировки.
- `Infrastructure` — настройки, пользовательские данные, горячие клавиши и захват экрана.
- `Assets` — тема интерфейса, словарь OCR и модели Tesseract. При сборке нужные ресурсы по-прежнему копируются в ожидаемые приложением пути.
- `Tests` — интеграционная проверка локального перевода на настоящей модели.

## Запуск

1. Установите .NET 8 SDK для Windows и восстановите пакеты NuGet: `dotnet restore ScreenTranslator.csproj`.
2. В меню выберите переводчик: «Hy-MT2 — локально» или «DeepL». Для локального режима нажмите «Настроить локальный перевод…» → «Скачать модель и движок». Для DeepL задайте API-ключ через «Настроить ключ DeepL…» или переменную `DEEPL_API_KEY`.
3. Соберите и запустите: `dotnet run --project ScreenTranslator.csproj`.
4. Для Windows OCR установите нужный языковой компонент распознавания Windows. Для Tesseract выберите движок в меню и нажмите «Настроить Tesseract…»: там можно указать `tesseract.exe` и каталог `.traineddata` моделей. Для русского нужны `rus.traineddata`, для английского — `eng.traineddata`. PaddleOCR требует нативные файлы, поставляемые с NuGet-пакетом.

При первом запуске старые `settings.json` и `dictionary.json` из папки программы копируются в `%AppData%\ScreenTranslator\`. Далее данные сохраняются там. При перезаписи создаётся резервная копия `.bak`. Если словарь повреждён, запись в него блокируется, чтобы не затереть исходные данные.

## Готовая сборка для Windows x64

Для запуска готового приложения используйте `publish\ScreenTranslator.exe`. Переносите на другой компьютер всю папку `publish`: в неё входят .NET 8 Desktop Runtime и необходимые библиотеки. Отдельная установка .NET для этой сборки не требуется. Локальная модель переводчика устанавливается отдельно через меню приложения.

Для создания такой сборки выполните из папки проекта:

```powershell
dotnet publish ScreenTranslator.csproj -p:PublishProfile=Windows-x64
```

Профиль `Properties\PublishProfiles\Windows-x64.pubxml` закрепляет Windows x64 и включает .NET 8.0.32. При обновлении встроенной .NET измените `BundledDotNetVersion` и повторите публикацию. Публикуйте в пустую папку либо обновляйте комплект целиком. Не смешивайте файлы сборки со встроенной .NET с файлами обычной сборки: оставшийся `hostfxr.dll` может заставить приложение искать среду выполнения в своей папке и показать ошибку «You must install or update .NET», даже если .NET уже установлена.

## Использование

По умолчанию Ctrl + Alt + Z выделяет область, Ctrl + Alt + X переводит весь рабочий стол, Ctrl + Alt + M открывает меню. Распознанный текст сразу отправляется на перевод. В меню настраиваются размер шрифта и прозрачность фона оверлея; статус OCR сообщает, найдена ли нужная языковая модель. Кнопка `+` у карточки слова позволяет проверить OCR перед сохранением. Режим «Авто» выбирает направление EN/RU по распознанным буквам, поэтому для короткого или смешанного текста лучше явно выбрать язык.

В локальном режиме текст обрабатывается на этом компьютере; запросы к DeepL и dictionaryapi.dev не выполняются. Карточки показывают локальный перевод и контекст захваченного текста. В режиме DeepL распознанный текст отправляется в DeepL, а карточки слов могут обращаться к dictionaryapi.dev.

## Локальный перевод Hy-MT2

Используются официальные `Hy-MT2-1.8B-Q4_K_M.gguf` и Windows x64 CPU-сборка `llama.cpp b11669`. Установщик скачивает закреплённые версии с GitHub и Hugging Face, проверяет SHA-256 и сохраняет их в `%LocalAppData%\ScreenTranslator\LocalTranslation`. Загрузка занимает около 1,15 ГБ; после установки интернет для перевода не нужен. Модель и движок не входят в Git-репозиторий. На другом устройстве их нужно один раз скачать через меню.

В настройке можно выбрать ранее скачанные `llama-server.exe` и файл GGUF, а также проверить перевод. Значения `LocalServerPath` и `LocalModelPath` в `settings.json` задают пользовательские пути; пустые значения означают стандартную папку. `TranslationProvider` принимает `deepl` или `local`; существующие настройки сохраняют DeepL до явного выбора локального режима.

Приложение само запускает скрытый процесс перевода на `127.0.0.1` со свободным портом и временным ключом доступа. Он работает только на CPU, использует не более четырёх потоков с пониженным приоритетом, остаётся загруженным между запросами и завершается при выходе из приложения или переключении на DeepL. Весь текущий диалог передаётся одним запросом; история между захватами не накапливается. Автоматического перехода с локального режима на облако нет.

Первый перевод включает загрузку модели и может быть заметно медленнее следующих. Отмена карточки слова отменяет её запрос; приложение проверяет, что движок освободился, и сохраняет модель в памяти. Если движок не отвечает, он завершается и запускается заново при следующем запросе. Окно контекста ограничено 8192 токенами, ответ — 2048 токенами. При превышении лимита приложение просит выделить меньше текста, а не показывает обрезанный перевод. Локальный режим используется в оверлее, карточках слов и словарной игре.

Источники, версии и лицензии перечислены в `THIRD_PARTY_NOTICES.md`.

## Проверка локальной интеграции

После установки модели выполните из папки проекта:

```powershell
dotnet run --project Tests\ScreenTranslator.LocalSmoke.csproj -c Release
```

Проверка выполняет настоящие переводы EN↔RU, пакетный перевод, проверяет ограничения ввода, отмену, завершение дочернего процесса и восстановление после отмены. Ключи и пользовательские настройки не изменяются.

## Проверка на Windows

Проверьте горячие клавиши при занятых сочетаниях, выделение на мониторе слева от основного и при разном масштабе дисплеев, миграцию данных из старой папки, а также восстановление `dictionary.json` из `.bak` после намеренной порчи копии файла.

## Исправление склеенных слов

Словарь `words.txt` теперь встраивается в сборку, а приложение исправляет короткие склейки и в режиме OCR «Авто», если в тексте больше латиницы. После замены исходников завершите старую копию через меню «Выход» (крестик только скрывает окно), затем выполните «Перестроить решение». Если другая копия программы всё ещё запущена, новая не стартует из-за защиты от второго экземпляра.
